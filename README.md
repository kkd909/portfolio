## Design Engineering Philosophy

The thing that breaks design systems isn't a lack of components. It's a detached instance. A hardcoded hex value where a token already exists. A spacing value that's 13px instead of 12px because someone eyeballed it. The system did the work. Someone chose not to use it.

I build governance into the system itself — so the right choice is the easy choice. Token architectures that enforce compliance by design. Audit tools that catch violations before they ship. Components built so inconsistency is structurally impossible.

On AI: I build interfaces where AI surfaces the menu of actions but never takes them. At law firms that means an attorney seeing what they need to act, not what the database happens to store. In a chronic care app it means a patient with compounded conditions getting one clear next action, not a dashboard. I don't automate the judgment. I compress the time it takes to get there.

On accessibility: WCAG compliance isn't a checklist I run at the end. It's the design system itself — built in from the token level. In the US, inaccessible products are legal liability under the ADA. I build above the floor because the alternative isn't a design choice — it's a risk.
